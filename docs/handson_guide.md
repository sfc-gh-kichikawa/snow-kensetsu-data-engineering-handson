# ハンズオン手順書

架空の建設会社「Snow建設」のデータ基盤チームに配属された皆さんの、ある1日です。各章では、登場人物の困りごとを Snowflake で解決します。

> データはすべて架空です。社名・人名・案件名・金額は、実在の企業・人物・案件とは関係ありません。

## 進め方の約束

- SQL を一から書く必要はありません。CoCo に日本語で頼みます。
- CoCo には、画面右のチャット欄から頼みます。
- SQL をファイルに書いてほしいときは、指示の最後に「〇〇の下に追記してください。実行はしないでください。」と付けます。手順書の指示文には、すでに入っています。
- 「CoCo への指示」は、そのままコピーして貼り付けてください。
- CoCo が書いたSQLは、内容を確認してから、自分で実行します。
- うまくいかないときは、手を挙げてください。`answers/` の正解SQLで追いつくこともできます。

## 事前準備（講師の指示があったときだけ）

ロールを ACCOUNTADMIN にして、`sql/00_setup.sql` をすべて実行します。最後に表示される確認の表で、4行とも「判定」が OK になっていれば完了です。

## 第3章 11:00 現場からデータが届く

**使うファイル**：`sql/03_pipeline.sql`

工事部長「渋谷の現場の工程が遅れている。機械が遊んでいないか？」

IICS（Informatica）から、重機の稼働ログのCSVが内部ステージ `IICS_LANDING` に届いた、という設定です。

### ① COPY INTO でロードする

1. `LIST @IICS_LANDING;` を実行し、ファイルが4本あることを確認します。
2. CoCo に次の指示を送ります。

```
@IICS_LANDING のCSVを MACHINE_LOG にロードする COPY INTO を、①の下に追記してください。実行はしないでください。
```

3. 件数を確認します（72,000行）。
4. CoCo が作った COPY INTO を、もう一度実行します。2回目は、ロードされるファイルが0本になります。

### ② Dynamic Table を作る

ファイルの「② Dynamic Table を作る」にある指示を CoCo に送ります。ファイルに追記されたSQLを確認して、実行します。

```
MACHINE_LOG・MACHINES・PROCESSES・PROJECTS から、現場・工程・重機の種類・1時間ごとの待機率、待機時間、損失（待機時間 × 時間単価 ÷ 60）を出す Dynamic Table 「SITE_MACHINE_IDLE」 を、②の下に追記してください。TARGET_LAG は1分、REFRESH_MODE は INCREMENTAL、ウェアハウスは ETL_WH です。列は PROJECT_ID、PROJECT_NAME、BRANCH、PROCESS_NAME、MACHINE_TYPE、HOUR_SLOT、TOTAL_MINUTES、IDLE_MINUTES、IDLE_RATE_PCT、IDLE_LOSS_YEN にしてください。実行はしないでください。
```

### ③ 新しいデータが届いたら？

1. ファイルの INSERT 文をそのまま実行します（渋谷の現場のクレーンから、待機の記録が届いた想定）。
2. 1分ほど待ってから、SITE_MACHINE_IDLE をもう一度照会します。渋谷みらいタワー新築工事が上位に来ます。
3. 更新の履歴を確認します。データが届いた直後だけ更新され、それ以外は `NO_DATA` になっています。

### ④ Task で毎朝7時の日報を作る

ファイルの「④ Task」にある指示を CoCo に送ります。ファイルに追記されたSQLを確認して、実行します。

```
毎朝7時（日本時間）に、前日の現場ごとの待機時間と損失を MACHINE_IDLE_DAILY に追加する Task MACHINE_IDLE_DAILY_TASK を、④の下に追記してください。テーブルも作り、ウェアハウスは ETL_WH、列名は下の確認用SQLに合わせてください。実行はしないでください。
```

続けて、ファイルの `EXECUTE TASK` で1回だけ実行し、実行結果と日報の中身を確認します。

## 第4章 12:00 明日の朝ピークに備える

**使うファイル**：`sql/04_scale.sql`

経理部長「毎朝7時半から9時は、レポートが遅くて仕事にならない」

1. 結果キャッシュを無効にして、約6億行の集計を XS で実行し、所要時間をメモします。
2. CoCo に「BI_WH のサイズを S に変更してください。」と送り、同じクエリをもう一度実行します。
3. 結果キャッシュを有効に戻して、同じクエリを2回実行します。2回目は一瞬で返ります。
4. サイズを XS に戻し、`SHOW WAREHOUSES` で、使っていないウェアハウスが SUSPENDED になっていることを確認します。

## 第5章 13:00 守りの運用

**使うファイル**：`sql/05_governance.sql`

人事部「給与の列は、人事部以外には見せないでほしい」
内部監査室「来週の監査で、権限とアクセスの記録を出してください」

| # | 内容 | 確かめること |
|---|---|---|
| ① | うっかり削除 | DROP したテーブルが UNDROP で戻る |
